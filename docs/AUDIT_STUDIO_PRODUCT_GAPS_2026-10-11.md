# FLUXCUE — comprehensive product gap audit / 2026-10-11

**Scope:** all 13 GitHub upstream equivalents already inventoried, current public FLUXCUE Vue/Three source, operator UX, 3D lighting, effects, cues, patch, deployment, test evidence and professional reliability. This is a **functionality/architecture audit**, not a claim of exhaustive per-file license review, competitive hands-on trials, accurate optical validation or production benchmarking. Source evidence is the pinned 2026-10-11 inventory in [UPSTREAM_SNAPSHOT.md](UPSTREAM_SNAPSHOT.md) and the project [AUDIT_OPEN_SOURCE.md](AUDIT_OPEN_SOURCE.md), supplemented with current upstream repository metadata and three pinned documentation/code-tree checks described below.

## Current source-of-truth status

- Baseline public `main`: `40ee265d3a8a77ca6d7c22c56887ae1d3cbfd9e3` before this PR. [PR #22](https://github.com/Rzbck/FLUXCUE/pull/22) contains the new editor/lighting/effect changes.
- The old UI had **colourized InstancedMesh LEDs with no real illumination of any 3D surface**. A 5mm square LED chip by itself does not generate shadows, bounce light or illuminate scenery in Three.js.
- The previous undo state was mixed with selection navigation and had a fallback that could substitute a *stale reactive baseline* for the actual drag-start snapshot. The fix uses the exact before-state of each edit, window capture on Ctrl+Z and a test-only SFC hook for reproducing Three TransformControls event sequences.
- 17 cue effect modes after this PR: six earlier plus eleven new deterministic patterns. They are **not** equivalent to an effect graph, palette engine, modifier stack, arbitrary media/video-texture mapper or sophisticated timecode sequencer.
- Stage preview now has a real Three.js lit floor/wall/occluder; at most eight representative SpotLight sources update from sampled LED colours, with 2 low/4 high shadow maps, ACES tone mapping and postprocessed UnrealBloomPass. It **approximates** LED emission and shadows. It does **not** trace photons from every LED, model calibrated emitter photometry, transmissive/scattering diffuser materials, lightfield caustics or global illumination. Sources outside the 8-sample preview budget cannot light surfaces yet; all LED pixels still have their own visible colours.
- No live network outputs, headless player, controller patch validator, VPS, private network or production stage safety gate changed here.

## Key actionable audit findings

1. **Do not treat passing Node pure tests as proof of mouse UX.** The first browser smoke CI attempted an incorrect Vite asset base and did not boot; the corrected run [38177837349](https://github.com/Rzbck/FLUXCUE/actions/runs/38177837349) passed Chromium WebGL/Vue mount plus 3 *synthetic* gizmo event sequences using **real Ctrl+Z/Ctrl+Shift+Z key events**. Actual physical pointer picking remains a separate acceptance item.
2. **Show-state navigation must never consume Undo.** Keeping selection and active cue browsing out of semantic history avoids one cause of no-op Ctrl+Z. Explicit gestures must commit the exact before snapshot, never adopt stale watcher changes.
3. **Previously LED colour did not illuminate anything.** The new stage surfaces/spotlights really can receive light and occlude shadows, but clustered 8-source sampling is an inexpensive approximation. No per-pixel photon tracing.
4. **17 effect names do not make a pro effect engine.** An actual composable descriptor/modifier/palette and parameter-editing pipeline is the highest leverage next milestone, then audio/video input adapters.
5. **Current project JSON schema is still `0.1.0` despite many extensions.** This is migration debt; version it before sharing projects broadly or connecting a headless engine.
6. **Browser-only localStorage is not an authoritative show controller.** Backup JSON and eventually a headless site player with a failover policy are required before professional installation use.
7. **No physically calibrated light or photobiological safety model.** Even the Strobe effect is merely an artistic preview and should include photosensitive-operator warnings and application-side frequency caps.

## Prioritized implementation plan and release gates

**Gate A — editor stability (now):** browser-backed global Undo and redo, 3D transform rollback proof, project import/export, cue colour locality; no further panel bloat until stable.

**Gate B — real scene and optical realism:** render pass + accurate stage surface shadows, selectable shadow/bloom quality, measured costs; then GLB and emissive fixture orientation; use actual diffuser geometry or documented beam approximations.

**Gate C — true creative effect architecture:** palette library, typed effect descriptors, parameterized 1D/2D/3D sources, spatial masks, layer routing, keyframes, audio features and media texture; save deterministic previews.

**Gate D — show authoring:** track/timeline editor, cue ownership and priorities, individual/overlap curve controls, hardware patch display, revisions and undo state.

**Gate E — hardware and deployment:** no real output until validated model/patch, protocol localhost replay, licensing boundary, stress and fault tests, owner-approved private Oracle and MikroTik deployment with local fallback.

This report is intentionally a **product/architecture inventory across all previously audited equivalents**, not an unsupported assertion that every upstream file or native build has been tested.
